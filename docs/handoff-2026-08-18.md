## Traps for whoever picks this up

- **`PeoplePicker`'s two `preventDefault`s are both load-bearing.** The one
  on each suggestion button's `onMouseDown` keeps the pick landing before
  blur; the new one on the list container keeps the scrollbar usable. Remove
  either and a symptom from this session comes back.
- **`reprintTask` keeps the identity discipline** — one appended row,
  untouched references everywhere else. It generates the new id *outside*
  the state updater so `setExpandedTaskId` can point at it; keep that shape
  if you touch it.
- **The history grouping nests a run only when its parent's row is in the
  table.** Runs of live jobs, orphaned runs, and legacy tasks are primary
  rows on purpose — "collapse everything under a parent" would make
  completed work unreachable when the parent isn't there. Don't "simplify"
  the `ids.has(t.parentId)` check away.
- **A JSX comment between attributes** (`<div /* … */ onMouseDown={…}>`,
  in the picker's list container) transpiles fine through Babel with the
  React preset — it's valid, not an accident to clean up.
